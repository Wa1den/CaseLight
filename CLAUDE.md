# CaseLight

Подсветка внутри системного блока как продолжение экрана. Управление железом — через
сервер OpenRGB (материнская плата, ленты и вентиляторы на её разъёмах, видеокарта, память).

WPF-приложение на .NET 9, только Windows, только x64.

## Сборка и запуск

```
dotnet build CaseLight.sln -c Release
```

```
dotnet publish src/CaseLight/CaseLight.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o dist
```

Утилиты из `tools` в solution не входят и собираются отдельно (`dotnet build tools/RgbProbe`).

Тестов нет. Проверка изменений — сборкой и запуском; для проверки раскладки без реального
экрана в приложении есть «тест размещения»: пятно, которое таскают мышью вместо кадра.

## Главная идея

Каждая светящаяся вещь описывается там, где она физически стоит — прямоугольником на
плоскости в миллиметрах, рядом с прямоугольником монитора. Диод берёт цвет с участка
экрана, ближайшего к своему месту: за пределами панели координата зажимается к кромке,
поэтому вентилятор справа от монитора показывает его правый край на своей высоте.

Отсюда всё остальное: `Arrangement` + `AnchorLed` + `EdgeOn` говорят, где внутри
прямоугольника сидит каждый диод, а `LedGeometry` превращает это в точки на сцене.

Два проекта.

**`src/CaseLight`** — само приложение.

| [Model/LedGeometry.cs](src/CaseLight/Model/LedGeometry.cs) | где сидит каждый диод: локально в 0..1, затем на сцене в мм; попадание мышью |

| [Rgb/OpenRgbTask.cs](src/CaseLight/Rgb/OpenRgbTask.cs) | задание планировщика: сервер стартует при входе с правами, без UAC |
| [View/SceneView.cs](src/CaseLight/View/SceneView.cs) | холст: монитор, фигуры, отдельные диоды; перетаскивание, поворот, размер |

| [MainWindow.Fixture.cs](src/CaseLight/MainWindow.Fixture.cs) | панель фигуры, раздел цветов, тест размещения |

**`src/CaseLight.Core`** — захват экрана, цвет, шина кадров, надзор за питанием.
Это своя копия общего кода, того же, что в [Rimlight](https://github.com/Wa1den/Rimlight):
подсветка корпуса обязана работать на машине, где нет ни ленты за монитором, ни контроллера
к ней, поэтому зависимости от того проекта быть не должно.

Из Core приложение реально трогает `HybridBackend`, `ZoneSampler`, `ColorPipeline`,
`FrameSubscriber`, `PowerWatcher`, `Native`, `ProbeLog`. `FramePublisher`, `SpoutBackend`,
`Metrics`, `GdiProbe` не используются — они оставлены, чтобы копия оставалась копией и
правки переносились между репозиториями без разбора расхождений. Не вычищать их как
мёртвый код.

## Оформление

Окно собирается кодом, XAML — только `App.xaml`: там объявлены `ThemeMode="System"`
(тема Fluent из .NET 9, отсюда светлая и тёмная тема вслед за системой, контролы и заголовок
окна в стиле Windows 11, Mica) и алиасы цветов поверх её токенов. Из-за экспериментального
статуса `ThemeMode` в csproj стоит `<NoWarn>$(NoWarn);WPF0001</NoWarn>`.

Своих цветов в коде нет. `Fg`, `FgDim`, `Warn`, `Panel`, `PanelStroke`, `PanelSolid` —
`SolidColorBrush` с `DynamicResource` на `Color`, поэтому один и тот же объект кисти меняет
цвет при переключении темы, и обновлять ничего не надо. Холст `SceneView` рисуется вручную и
достаёт те же алиасы через `TryFindResource`.

Грабли, на которые уже наступали:

* У Fluent-чекбокса `MinWidth` 120: короткая подпись растягивается, и значок подсказки
  уезжает вправо от текста. Ставить `MinWidth = 0`.
* Подсказка наследует шрифт своего элемента, а у значка это шрифт иконок без букв. Тексту
  подсказки задавать `Segoe UI` явно.
* `CardBackgroundFillColorDefault` полупрозрачен. Для панели поверх холста нужен
  `PanelSolid` (`SolidBackgroundFillColorBase`), иначе сквозь неё видно сетку.
* Ресурсы объявлены в приложении, а не в окне, поэтому индексатор `Window.Resources` вернёт
  null. Искать через `TryFindResource`.

## Что нужно знать, прежде чем править

**Устройства OpenRGB адресуются по имени, а не по индексу.** Список перенумеровывается от
любого изменения детекторов, и сохранённая привязка по индексу молча начинает светить не
тем. `RgbHub.Generation` растёт при каждом перечитывании списка; `CasePainter` замечает это
и пересобирает разрешённые индексы.

**Сервер OpenRGB падает — это ожидаемое состояние, а не ошибка.** Обрыв связи обрабатывается
переподключением, после которого заново выставляется прямой режим у каждого устройства.
Запись в устройства идёт только под `_io`, потому что клиентская библиотека не потокобезопасна,
а до неё дотягиваются два потока: раскраска и интерфейс.

**Порт открывается раньше, чем сервер находит железо.** Подключение и готовность — разные
вещи: `IsReady` требует непустой список устройств.

**После сна железо нужно оставить в покое.** Контроллеры переучитываются, сервер держит
старые ручки и рапортует об успехе в пустоту. Отсюда `ResumeDelayMs` (пауза перед первой
записью) и `WakeRecovery.RestartServer` по умолчанию — грубо, но работает.

**Имя экрана `\\.\DISPLAYn` — не идентификатор.** Windows раздаёт эти имена в порядке
обнаружения выходов, и перестановка кабеля между разъёмами видеокарты их перенумеровывает:
за одну сессию ультраширокий и портретный экраны поменялись именами. Выбранный экран
хранится моделью из EDID (`Scene.MonitorModel`), имя остаётся только чтобы различить два
одинаковых монитора. Разбор в [Model/ScreenChoice.cs](src/CaseLight/Model/ScreenChoice.cs).

**Габарит фигуры на холсте — это диоды плюс область выборки.** Раскраска берёт участок
`u ± SampleRadiusMm` вокруг каждого диода, поэтому рамка отстоит от них ровно на это
значение с каждой стороны и показывает, что фигура читает. У плоских форм — полосы и
кольца, стоящего ребром, — поперёк задавать нечего: там весь размер даёт область выборки,
и тянется только длина.

**Медленные шины.** Память сидит на SMBus; писать в неё каждый кадр — задерживать всё
остальное. У каждой фигуры свой делитель `UpdateEvery`, устройство пишется по самому
частому из требований своих фигур (частично записанное устройство погасило бы остаток).

**Несколько фигур могут делить одни диоды** (три вентилятора, спаянных параллельно, — это
один прогон на 32 диода в трёх разных местах). Вклады усредняются, а не затирают друг друга.

**Раскладка сохраняется в `%AppData%\CaseLight\scene.json`**, там же `caselight.log` и папка
`lang`. Битый файл настроек не роняет запуск — сессия начинается с пустой сцены.

**Список фигур читается из потока раскраски**, поэтому изменения списка идут под
`lock (Scene.Fixtures)`.

## Соглашения

* Doc-комментарии `///` — по-английски, объясняют **почему** так, а не что делает код;
  часто с конкретикой из отладки («сервер умер через 41 секунду после пробуждения»).
  Внутристрочные комментарии — по-русски. Держаться этого стиля.
* Интерфейс и статусы — по-русски, сухо: без олицетворений, разговорных слов, сокращений
  и обращений к пользователю на «ты». Механизм переводов (`Core/Text/Loc`) достался от общей
  библиотеки и в приложении не задействован, кроме одной строчки настройки пути.
* Коммиты — по-русски, одной фразой по существу изменения.

## Старое имя Ambilight

Общий проект когда-то назывался **Ambilight** и переименован в **Rimlight**. В коде старое
имя осталось ровно в одном месте — `FrameBus.MapName` = `Local\AmbilightFrameBus`. Это
контракт между процессами: имя открывают обе стороны, и переименовать его можно только
одновременно в обоих репозиториях, без всякой пользы взамен.

Значение перечисления `CaptureSource` переименовано в `FromRimlight`, но в настройках,
записанных раньше, стоит `FromAmbilight`, поэтому `CaptureSourceConverter` понимает оба
имени. Неизвестное имя не бросает исключение, а откатывается к значению по умолчанию:
`Scene.Load` на битый файл отвечает пустой сценой, то есть любое исключение здесь стоит
пользователю всей раскладки.
